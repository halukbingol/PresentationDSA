Stacks and Stacks Using Arrays in Java -- six Beamer decks
==========================================================

decks/stack-1-concepts    stack-concepts.tex    LIFO, the ADT, array + top, push/pop algorithms, growing,
                                                cost, applications (brackets, postfix, call stack), Java classes
decks/stack-2-examples    stack-examples.tex    real programs: IntStack, ArrayStack<T>, reversing, brackets,
                                                postfix, binary, undo/redo, call stack, ArrayDeque, java.util.Stack
decks/stack-3-freshman    stack-freshman.tex    install, IntStack step by step, tracing, an interactive stack,
                                                five common mistakes with their real error messages
decks/stack-4-sophomore   stack-sophomore.tex   interface + generic ArrayStack<T>, iterator, generic arrays,
                                                copy counts and amortized cost, loitering, tests, shunting yard, Deque
decks/stack-5-junior      stack-junior.tex      linked vs array, boxing, benchmark, bytes per element, potential
                                                method, thrashing, recursion and -Xss, DFS, fail-fast iterators
decks/stack-6-senior      stack-senior.tex      JVM operand stack (javap), thread stacks, StackWalker, virtual
                                                threads, data races, Treiber lock-free stack, ABA, deep-nesting
                                                attacks, API design (Stack vs Deque, SequencedCollection)

hblib/                    the libraries and template from hblib.zip (unchanged)

Building a deck (Windows: Command Prompt; macOS: Terminal)
-----------------------------------------------------------
  cd decks/stack-3-freshman
  pdflatex stack-freshman.tex       (twice, for i/N and the outline)

Programs and their outputs
--------------------------
Every output on the slides is REAL (JDK 21, Linux):
  codeoutput/<Name>.java     a program; classes without main() (IntStack, ArrayStack, ...) are only compiled
  codeoutput/<Name>.in       its keyboard input, .args its arguments, .jvmargs its JVM options (optional)
  codeoutput/<Name>.sh       a terminal session, run in a copy of codeoutput/<Name>/
  codeoutput/<Name>.txt      what it printed, regenerated by:   bash run_examples.sh  [Name.java]
                             (macOS: Terminal; Windows: Git Bash)
Timings (benchmark, virtual threads), memory sizes, stack depths and the data race change from run to run.
JUnit, JMH and Maven/Gradle listings are marked "Not run here".
